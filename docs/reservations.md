# 祈福卡预约配置

配置文件：`apps/web/src/lib/reservation-config.json`。

- `enabled`：默认 false。完成邮箱验证及实际收件测试后再改为 true。
- `recipientEmail`：接收预约的邮箱，默认留空。公开网页里的配置不是秘密，勿填写密码或 API key。
- `formToken`：FormSubmit 验证邮箱后提供的隐藏邮箱 token，可替代公开邮箱；填写后优先使用 token。
- `prices.card` / `prices.gift`：每份参考价格，数字，默认 null 显示“价格待确认”。不是已收款金额。
- `currency`：默认 CNY。报价暂不含自动计算的寺庙费用和运费，最终费用由人工确认。

## 开通

1. 按 https://formsubmit.co/documentation 的步骤，使用收件邮箱提交一份测试表单并点击邮箱中的验证链接。可先在 FormSubmit 官网完成验证，网站开关仍保持 false。
2. 填入收件邮箱或验证后取得的 token，配置参考价格。价格可继续留空。
3. 在本地预览中设置 enabled=true，提交你自己的测试联系方式，完成 FormSubmit 的验证，确认邮箱确实收到卡款、数量、预约编号、称呼、联系方式与备注。
4. 测试成功后提交并推送 main，检查 Publish website 工作流。再从线上实际提交一份测试预约验证收件。

网站使用原生 HTTPS POST 跳转 FormSubmit，保留服务的验证码与提交结果页面。无需部署服务器、无需邮箱密码。没有配置或未开启时不能发送，不会显示虚假的成功提示。失败时以服务返回的页面为准，返回可重试；同一次表单保留相同预约编号，人工处理时按编号去重。

预约并非付款、订单确认或寺庙受理。运营者收到邮件后人工确认寺庙、价格、时间，再收款及收取配送地址。表单不收配送地址，不在 localStorage 保存联系方式。用户须同意通过 FormSubmit 发送给运营者；表单服务自身的数据处理及保存规则见其文档和隐私政策。未配置真实邮箱，无法验证实际邮件送达；上线开关不应代替收件测试。

## 用户入口

抽卡页不展示预约。用户从原画详情底部或“我的路径”的“看看实体收藏卡”进入，先看实体卡示意和参考信息，自愿选择寺庙祈福（默认不选），再填写并核对预约。邮件中的“寺庙祈福 / Temple blessing”记录用户选择；未选择时仅按实体卡意向跟进，不能默认安排仪式。材质、尺寸和寺庙细节未确定时如实显示待确认。
